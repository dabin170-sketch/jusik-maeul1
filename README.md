# 🐹 주식마을: 동물들의 월스트리트 — v4.0 (4인 멀티플레이어)

혼자 플레이는 예전처럼 `index.html` 하나로 돌아가요.
**친구들과 플레이**는 실시간 서버가 있어야 해서 `server` 폴더가 함께 들어 있어요.

```
📁 저장소
├─ index.html        ← 게임 화면 (혼자 플레이 + 친구들과 플레이)
├─ render.yaml       ← Render에 올릴 때 쓰는 설정
├─ README.md         ← 지금 이 문서
└─ server/
   ├─ server.js      ← 방·초대 코드·날짜 진행·주문 체결·저장을 맡는 서버
   ├─ engine.js      ← index.html 안의 게임 엔진을 서버에서 그대로 돌리는 장치
   ├─ storage.js     ← 저장소 (PostgreSQL 또는 파일)
   ├─ package.json
   └─ test/          ← 자동 검사 (npm test)
```

## 1. 내 컴퓨터에서 먼저 해 보기

1. [Node.js](https://nodejs.org) 20 이상을 설치해요.
2. 터미널에서 아래 명령을 차례로 입력해요.
   ```
   cd server
   npm install
   npm start
   ```
3. 브라우저에서 `http://localhost:3000` 을 열어요.
4. 「👫 친구들과 플레이 → 🏡 새 마을 만들기」로 마을을 만들어요. 다른 브라우저 창(시크릿 창도 돼요)에서 같은 주소로 들어가 「🔑 초대 코드로 입장하기」를 눌러 보세요.

같은 와이파이를 쓰는 친구는 `http://내컴퓨터IP:3000` 으로 들어올 수 있어요. 멀리 있는 친구와 하려면 아래처럼 인터넷에 올려야 해요.

## 2. 인터넷에 올리기 (Render + Neon, 무료로 시작)

**왜 GitHub Pages만으로는 안 되나요?**
GitHub Pages는 파일을 보여 주기만 해서, 네 사람의 주문을 받고 날짜를 진행하는 서버를 돌릴 수 없어요. 그래서 다음 두 서비스를 함께 써요.

- **Render**: 웹소켓(실시간 연결)을 지원하는 서버를 무료로 돌릴 수 있어요. GitHub 저장소를 연결하면 자동으로 올라가요.
- **Neon**: 무료 PostgreSQL 데이터베이스예요. Render 무료 서버는 다시 켜질 때 서버 안의 파일이 지워지기 때문에, 마을 저장은 데이터베이스에 해야 안전해요.

### 순서
1. 이 폴더 전체(`index.html`, `render.yaml`, `server/`)를 GitHub 저장소에 올려요.
2. [neon.tech](https://neon.tech)에 가입하고 프로젝트를 만든 뒤, **Connection string**(`postgresql://...` 로 시작)을 복사해요.
3. [render.com](https://render.com)에 가입하고 **New → Blueprint**를 눌러 저장소를 고르면 `render.yaml` 대로 서버가 만들어져요.
4. 설정 화면에서 환경 변수 **`DATABASE_URL`** 에 2번에서 복사한 주소를 붙여 넣어요.
5. 배포가 끝나면 `https://jusik-maeul.onrender.com` 같은 주소가 생겨요. 그 주소를 친구들에게 보내면 끝이에요.
   - 대기실의 「초대 링크 복사」 버튼을 누르면 `…/?room=HAM-7K2P` 처럼 코드가 들어간 링크가 복사돼요.

> ⚠️ Render 무료 서버는 15분 동안 아무도 접속하지 않으면 잠들어요. 다음 접속 때 깨어나는 데 30초~1분 걸릴 수 있어요. 마을은 데이터베이스에 저장돼 있어서 사라지지 않아요.

### 게임 화면은 GitHub Pages에 두고 싶다면
`index.html` 맨 아래쪽 `SERVER_URL = ''` 에 Render 주소를 적거나(예: `'wss://jusik-maeul.onrender.com/ws'`), 게임 첫 화면 「⚙️ 설정」에서 서버 주소를 적으면 돼요.

## 3. 환경 변수

| 이름 | 뜻 | 기본값 |
|---|---|---|
| `PORT` | 서버가 쓰는 포트 | 3000 (Render는 자동 지정) |
| `DATABASE_URL` | PostgreSQL 주소. 있으면 데이터베이스에, 없으면 `server/data/`에 파일로 저장 | 없음 |
| `DATA_DIR` | 파일 저장 폴더 | `server/data` |

## 4. 어떻게 작동하나요?

- **한 방 = 한 경제.** 방마다 서버 안에 게임 엔진이 하나씩 있고, 방마다 난수 씨앗이 달라요. 다른 방과 시장이 섞이지 않아요.
- **같은 시장, 각자의 계좌.** 네 사람의 게임 상태는 모두 같은 씨앗에서 출발해요. 개인 행동(주문·환전 등)은 시장 난수를 건드리지 못하게 막아 두었어요. 그래서 네 사람의 주가·뉴스·경제는 항상 똑같고, 계좌만 따로 움직여요. 서버는 날짜가 바뀔 때마다 네 사람의 시장이 정말 같은지 지문을 비교해서 확인해요.
- **서버만 결정해요.** 날짜 진행, 주가, 경제 이벤트, 주문 체결, 계좌 계산, 저장, 순위는 모두 서버가 해요. 브라우저에서 주가나 돈을 바꿔도 서버 상태는 바뀌지 않아요.
- **미래 정보는 보내지 않아요.** 시장 난수 상태, 씨앗, 오늘의 남은 가격 경로, 숨은 시장 국면, 예정된 후속 사건은 브라우저로 보내기 전에 지워요.
- **주문 순서**: 플레이어 확인 → 방 참여 확인 → 종목 확인 → 주문 가능 상태 → 잔고·보유 수량 → 주문 조건 → 서버 체결 → 계좌 변경 → 거래 기록 → 결과 전송. 주문마다 고유 번호가 있어서, 네트워크가 끊겨 다시 보내도 두 번 체결되지 않아요.
- **시장 진행 방식**
  - 공동 턴제(추천): 모두 「준비 완료」를 누르면 다음 거래일로 넘어가요. 접속한 사람만 셉니다.
  - 자동 진행: 서버 시계로 장중 10분씩 흘러가요. 장중에 시장가로 바로 사고팔 수 있어요.
- **접속이 끊기면**: 계좌는 서버에 그대로 남아요. 남은 사람끼리 계속할 수 있고, 그동안의 가격 변화는 끊긴 사람의 계좌에도 똑같이 반영돼요. 다시 들어오면 서버의 최신 상태를 먼저 받아요.

## 5. 복구 코드 정책

- 처음 들어올 때 서버가 나만의 **복구 코드**를 만들어 이 기기에 저장해요. 서버에는 원문이 아니라 해시(지문)만 저장돼요.
- 닉네임이나 초대 코드만으로는 남의 계좌에 들어갈 수 없어요. 초대 코드는 마을을 찾는 용도일 뿐이에요.
- 다른 기기로 옮길 때는 「📊 성적표 → 🔐 내 공개 설정 → 복구 코드 보기」로 코드를 복사해 두었다가, 새 기기에서 「♻️ 복구 코드로 돌아가기」에 넣어요.
- **복구 코드를 잃어버리면 방장도 서버도 그 계좌를 되찾아 줄 수 없어요.** 자리가 남아 있다면 새 주민으로 다시 들어올 수 있어요.

## 6. 방장이 할 수 있는 것과 없는 것

- **할 수 있어요**
  - 게임 시작, 방 설정 변경(게임 중에는 진행 방식과 수익률 공개만)
  - 준비 상태 확인, 플레이어 추방, 방장 위임
  - 일시정지, 다음 날 진행 요청(20초 뒤 진행), 공동 시나리오 시작(60거래일에 한 번), 투자왕 리그 시작, 저장
- **할 수 없어요**
  - 다른 사람의 계좌 수정이나 비공개 정보 열람
  - 게임 중에 경제 규칙(변동성·위기 빈도·시작 금액) 변경

## 7. 자동 검사

```
cd server
npm test               # 4명 입장·5번째 거절·동시 주문·중복 주문·준비 투표·재접속·서버 재시작 복원·위조 차단 등 30가지
node test/auto.test.js # 자동 진행 모드
```

⚠️ 게임 속 회사·인물·돈·뉴스는 모두 가상이며 실제 투자 권유가 아니에요.
